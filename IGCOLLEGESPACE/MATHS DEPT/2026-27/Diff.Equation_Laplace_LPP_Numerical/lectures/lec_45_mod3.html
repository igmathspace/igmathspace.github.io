  • Recognise the four special cases of the simplex method from the final tableau
  • Detect and handle degeneracy — when a basic variable becomes zero
  • Detect and interpret an unbounded solution
  • Detect multiple optimal solutions
  • Recognise an infeasible solution
  • Review the complete simplex procedure
📐 2. Four Possible Outcomes of the Simplex Method

When the simplex method is applied to a linear programming problem, exactly one of the following four cases will occur in the final tableau:

  1. Unique optimum — the usual case; the method terminates with a single optimal basic feasible solution.
  2. Multiple (alternate) optimal solutions — more than one optimal basic feasible solution exists.
  3. Unbounded solution — the objective function can be increased (or decreased) indefinitely.
  4. No feasible solution — the constraint set is inconsistent; the feasible region is empty.
🔁 3. Multiple Optimal Solutions
Detection rule

Multiple optimal solutions exist if, at the optimal tableau, the net evaluation \(Z_j - c_j = 0\) for at least one non-basic variable. Then introducing that variable into the basis yields another optimum with the same objective value — the objective function is parallel to an edge of the feasible region.

Interpretation

If the iso-profit line (in 2-D) is parallel to one of the binding constraints, every point on that edge is optimal. The simplex method finds one such optimum; the other optima are obtained by allowing the zero-\(Z_j - c_j\) variable to enter the basis.

♾️ 4. Unbounded Solution
Detection rule

An unbounded solution is detected when, at some iteration, the entering variable is chosen (has the most negative \(Z_j - c_j\)) but all entries in the key column are zero or negative. In that case no leaving variable can be found (all ratios would be negative or infinite), and the objective can be increased indefinitely by letting the entering variable grow without bound.

Interpretation

The feasible region extends to infinity in some direction, and the objective function increases along that direction without bound. This usually signals a modelling error (missing constraints).

⚠️ 5. Degeneracy
Definition and detection

A basic feasible solution is degenerate if at least one basic variable has the value zero. Degeneracy arises during the simplex method when, in the ratio test, two or more rows tie for the minimum ratio — or when the RHS value \(b_i\) of a constraint is zero.

Consequences
  • The objective value may not improve in some iterations (the next tableau yields \(Z\) equal to the previous \(Z\)).
  • In rare pathological cases, the algorithm may cycle (return to a previous tableau) without ever reaching the optimum. This is called cycling.
  • In practice, cycling is extremely rare; Bland's rule (tie-breaking by lowest index) guarantees termination.
  • The method still finds the optimum, provided the problem has one.
⚠️ CAUTION! Degeneracy is not an error — it is a legitimate property of certain LPPs. The simplex method must be carefully implemented to handle ties (choose any tie-broken row, but be aware that the number of iterations may increase).
❌ 6. Infeasible Solution
Detection rule

When artificial variables are used (Big-M or two-phase method), an infeasible solution is detected if, at the final tableau, at least one artificial variable remains in the basis at a positive value. This means the constraints are inconsistent — no feasible solution exists.

Interpretation

The feasible region is empty — no point satisfies all constraints simultaneously. Infeasibility depends only on the constraints, not on the objective function.

Note: For \(\le\)-type LPPs (as solved by the basic simplex in Lecture 43), the initial basic feasible solution always exists (all slacks form a basis), so infeasibility cannot occur. Infeasibility is only relevant when the model contains \(\ge\)-type or equality constraints requiring artificial variables.

Problem 1 (Multiple optimal solutions). Maximise \(Z = x_1 + x_2\), subject to \(x_1 + 2x_2 \le 4,\; x_1 \le 2,\; x_1, x_2 \ge 0\). Show that the problem has multiple optimal solutions. CO3

Max \(Z = x_1 + x_2 + 0s_1 + 0s_2\), s.t. \(x_1 + 2x_2 + s_1 = 4,\; x_1 + s_2 = 2\).

Problem 3 (Degeneracy). Maximise \(Z = 2x_1 + x_2\), subject to \(x_1 + x_2 \le 4,\; 2x_1 + 2x_2 \le 8,\; x_1, x_2 \ge 0\). Show that the problem has a degenerate basic feasible solution. CO3
✅ Step-by-step:
Step 1: Note that the second constraint is 2 × the first — these are redundant. The first constraint is binding at the optimum, and the solution will be degenerate because only one independent constraint is active at the vertex.
Step 2: Standard form: \(x_1 + x_2 + s_1 = 4,\; 2x_1 + 2x_2 + s_2 = 8\).
Step 3: Initial BFS: \(s_1 = 4, s_2 = 8\); \(x_1 = x_2 = 0\); \(Z = 0\).
Step 4: Iteration: \(x_1\) enters (net eval −2). Ratio test: \(4/1 = 4\), \(8/2 = 4\) — tie! This is the first hint of degeneracy.
Step 5: Pivot on \(s_1\)-row (tie broken by lower index). New tableau:

Step 6: Now \(s_2 = 0\) is a basic variable with value zero — the solution is degenerate.
Step 7: Next iteration: \(x_2\) enters (net eval −1). Ratio test: \(x_1\)-row 4/1 = 4; \(s_2\)-row has coefficient 0 (not considered). So \(x_1\) leaves. New tableau:
Basic\(c_B\)\(x_B\)\(x_1\)\(x_2\)\(s_1\)\(s_2\)

Step 8: Not optimal (net eval −1). \(x_1\) enters. Key column = \(x_1\). \(s_2\)-row has 0, so only \(x_2\)-row (coefficient 1). Ratio = 4/1 = 4. \(x_2\) leaves. New tableau is the one from Step 5 — we have cycled! This is a manifestation of degeneracy.
Step 9: Actually if we break ties differently at Step 5 (pivot \(s_2\) instead of \(s_1\)), we get a non-cycling path. This illustrates the cycling phenomenon caused by degeneracy.
Note: In this example the objective is actually unbounded: from the initial feasible region, \(Z\) can go to infinity in the direction where both constraints are satisfied (since the second is redundant). The degeneracy and unboundedness interact here.

✅ Degenerate BFS arises (\(s_2 = 0\) basic) whenever ratios tie; cycling may occur unless tie-breaking is controlled.

Problem 4 (Review — full solution). Solve: Maximise \(Z = 2x_1 + 5x_2\), subject to \(x_1 + 4x_2 \le 24,\; 3x_1 + x_2 \le 21,\; x_1 + x_2 \le 9,\; x_1, x_2 \ge 0\). CO3
✅ Complete review solution (see Lecture 43 for the full tableau sequence):
Iteration 0 (initial BFS): \(x_1=0, x_2=0, s_1=24, s_2=21, s_3=9\); \(Z=0\).
Iteration 1 (after pivoting \(x_2\) into basis in place of \(s_1\)): \(x_1=0, x_2=6, s_1=0, s_2=15, s_3=3\); \(Z=30\).
Iteration 2 (after pivoting \(x_1\) into basis in place of \(s_3\)): \(x_1=4, x_2=5, s_1=0, s_2=4, s_3=0\); \(Z=33\).
Optimality check: all net evaluations \(Z_j - c_j \ge 0\) → optimal. Also, no non-basic variable has \(Z_j - c_j = 0\) → the optimum is unique.

✅ \(x_1 = 4,\; x_2 = 5,\; Z_{\max} = 33\), unique optimum.

📋 10. Quick Summary
  • Unique optimum: all net evaluations nonzero for non-basic; the usual case.
  • Multiple optima: at least one non-basic variable has \(Z_j - c_j = 0\) at the final tableau.
  • Unbounded: key column has no positive entries; ratio test fails.
  • Degenerate: a basic variable is zero; arises from tied ratios; may cause cycling.
  • Infeasible: artificial variable remains positive in the final basis (Big-M context).
  • Review: Module III covers LPP from definition through graphical methods, forms and the simplex algorithm.
